# Git 操作のルール（AI 向け）

Git の状態を変える操作をするときに読む指示です。パスは `.github/` からの相対パスです。

## 基本

- 人が明示的に指示しない限り、Git の状態を変えないでください。
- 読み取りだけの操作（`status`、`diff`、`log`、`show`、`blame` など）は、指示がなくてもしてかまいません。

## 対象になる操作

次のような、Git の状態を変える操作すべてです。

- `add`、`commit`、`push`、`pull`、`fetch`
- `reset`、`restore`、`checkout`、`switch`、`clean`、`stash`
- `merge`、`rebase`、`cherry-pick`、`revert`
- ブランチやタグの作成・削除・切り替え

## 許可の範囲

- ファイルの作成や編集を任されても、Git 操作まで任されたことにはなりません。
- 作業を任されても、`push` などの外部への公開まで任されたことにはなりません。
- `push` は人が行います。最後の安全装置なので、AI は `push` しないでください。必要なときは、人に `push` を頼んでください。
- 指示された操作だけを行ってください。たとえば「コミットして」は、そのコミットに必要なステージと新しいコミットだけを含みます。既存のコミットの修正（`--amend` など）や `push` は含みません。
- 直前のコミットへの追加（`--amend`）は、`.ai/commit.md` の条件に従い、明示的な指示があるときだけ行ってください。
- 取り消しにくい操作（`reset --hard`、`clean`、強制 `push`、ブランチの削除など）は、指示があっても、実行前に対象を示して確認してください。

## 作業ツリーとステージの扱い

- 今の staged / unstaged / untracked の状態をそのまま尊重してください。人がステージを使って変更を確かめていることがあります。
- 指示された対象以外の変更をステージしたり、戻したりしないでください。
- 対象外の変更を巻き込まずに進められない場合は、作業を止めて人に確認してください。
- コミットのときは、ステージの状態がコミットの対象と一致しているかを確かめてください。ステージを変えるのは、違いを示して人の承認を得てからです（`.ai/commit.md`）。

## コミットするとき

- コミットの単位やメッセージなどは `.ai/commit.md` に従ってください。
